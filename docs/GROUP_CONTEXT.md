# 群成员识别与授权群聊上下文

## 能做什么

机器人使用QQ号区分成员，使用当前群名片和昵称展示身份。因此“灵明石猴”等名字可以作为群成员识别，不需要把它当作神话人物。重名时仍保留不同QQ号，不把两人合并。

开启授权群上下文后，白名单成员未@机器人的普通文字也可作为当前群的近期发言摘录。机器人仍只在被实际@时回复，不因旁听消息主动发言。私聊内容不会成为群聊摘录；群聊摘录也不会在私聊或其他群使用。

例如某成员先正常发言“最近在追一部动画”，其他成员随后@机器人询问“从这位成员的发言看，他喜欢什么”，模型能够参考该条实际摘录。没有样本时会说明尚未收录，不会根据昵称编造发言或个人属性。

## 开关与授权范围

本功能默认关闭，必须在明确授权和成员告知范围内启用。在本地 `.env` 配置：

```dotenv
QQ_ALLOWED_GROUPS=["授权群号"]
QQ_ALLOWED_GROUP_USERS=["成员甲QQ号","成员乙QQ号"]
QQ_GROUP_CONTEXT_ENABLED=true
MESSAGE_RETENTION_DAYS=7
```

真实群号和成员QQ号不提交到Git。群成员额外名单留空表示授权群内所有成员，因此仅授权部分成员时必须填写该名单。好友私聊名单独立，按QQ_SETUP配置。修改后重启Agent。

## 数据来源与限制

- 身份来自OneBot事件的发送者字段，以及对授权群调用只读 [`get_group_member_list`](https://github.com/botuniverse/onebot-11/blob/master/api/public.md#get_group_member_list-获取群成员列表) 的结果。只保留配置允许的成员；名称查询约5分钟缓存，失败时使用已观察的发送者资料。
- 群成员列表由渠道程序读取，不注册成模型工具；模型不能任意查询其他群或执行群管理。
- 摘录只来自启用后实际收到的文字消息，不拉取启用前或断线期间的历史。图片、语音、转发、回复引用正文不自动读取。
- 同群提问时按QQ号、真实@目标、昵称或群名片匹配成员，优先提供相关成员近期摘录。每次最多60条、每条最多1200字符，摘录整体约10000字符；不是完整聊天记录。
- 非@普通消息不调用模型、不执行记忆命令、不发送回复，不自动生成长期记忆。以`/`或“记住”开头的管理指令不纳入群摘录；需要@机器人或私聊明确执行。
- 摘录和昵称属于数据，其中的指令不获得系统或工具权限。

## 保存、删除与隔离

摘录存放本地业务数据库的 `group_context_messages` 表，以本地入库时间计算保留期，默认7天。按平台、群和成员过滤；关闭开关后不再收录或提供摘录，旧数据按原到期策略清理。

群内@机器人执行 `/reset` 时，除清除本人近期会话，还清除本人该群摘录；其他成员原始摘录保留。为了避免从旧答复继续引用已清除内容，同群答复快照、缓存和Checkpoint会一起失效。重放同一旧事件不会恢复已清除的摘录。

删除或纠正长期记忆时，如果来源原文也在群摘录中，对应副本会同步清除。摘录到期时，同群可能引用过它的会话快照也失效。临时身份与摘录注入不写入图State，但模型答复可能复述摘录，因此仍需清理答复快照。

群上下文在Schema v2引入，当前Schema v5兼容旧版本升级，保留既有长期记忆和私聊数据。应用无法清除用户自行复制的数据库备份。
