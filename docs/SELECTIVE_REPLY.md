# 选择性接话

功能已实现，初始off。普通群消息继续按授权范围保存；只有本群管理者明确启用on后才会主动回复。私聊保持原行为，/style的全体群成员权限不变。

## 命令

在授权群内实际@机器人：

```text
/auto status
/auto shadow
/auto on
/auto off
/auto cooldown 90
/auto limit 6
```

status供授权成员查看，显示模式、滚动小时发送/判定额度、冷却和最近原因。开关和参数只允许本地 `.env` 的 `QQ_CONTROL_USERS` 管理者修改；名单用JSON字符串数组，真实号码不提交Git。管理者可在授权群内使用/auto，不因此获得普通聊天或群摘录权限。修改管理者名单后重启。

shadow只调用模型判断并保存统计，不发送候选草稿；它仍消耗API额度。on才发送。off立即取消未发送的候选，恢复仅@回复；已经发出的消息不能撤回。cooldown范围30～3600秒，limit范围1～60次/小时，配置按群保存，重启后保留。

## 默认行为

- 90秒普通主动发送冷却、每群滚动1小时最多6次发送。
- 每群滚动1小时最多20次模型判定，判定至少间隔20秒。
- 等待4秒观察，每群最多保留一个最新候选；新消息取消旧候选，不排长队。入站超过30秒的候选丢弃。
- 明显问题、求助、叫机器人及少量吃饭/疲惫/学习话题作为候选；简单附和、命令、@其他人、非授权群/成员跳过。规则筛选后模型仍可skip。
- 机器人答复后30秒内同一成员可明确续聊，最多2次，绕过普通90秒冷却，仍受发送和判定预算限制；其他成员发言结束该窗口。
- 一次模型调用同时生成判断和草稿，8秒超时，严格校验JSON；错误/超时/格式错误/工具调用均静默跳过。不开放工具。
- @与私聊使用优先队列，先补齐此前待入库的群上下文；主动判定不占用显式请求的工作队列。/auto控制不被普通3秒请求限流丢弃，实际发送仍遵循发送间隔。
- 每条模型答复最多70字符，使用当前基础规则、默认人格和/style微调。

发送前重查开关、额度、入站年龄、队列优先状态及授权快照指纹。新消息、style修改、记忆删除、reset或到期导致版本变化时丢弃旧草稿。续聊包含该成员最近两轮已完成的公开群对话，过滤工具协议；这些内容参与同样的快照失效检查。主动模型生成在持久化锁外，快照读取与发送复核在锁内，保留已有数据隔离规则。

## 持久化与恢复

Schema v4兼容v1/v2/v3升级：auto_settings保存逐群模式/频控，auto_events保存判定去重和发送尝试，auto_status保存最近原因。滚动额度跨重启保留；候选及续聊窗口不恢复，断线取消，不补发旧主动消息。

发送尝试前持久占用发送额度；ACK不确定仍计入额度且不重试。成功答复保存到触发成员的群会话及缓存，参与原有7天清理、删除与失效流程。skip和shadow不写入助手答复。私聊、private/global记忆不加入群候选提示词。

日志记录固定原因、模型耗时与Token用量，不保存判断思路或完整正文。auto_events按原保留期清理，配置独立保留。

建议先开启shadow观察20～30条有代表性的聊天，检查候选频率和最近原因，再使用on；不以固定等待时间代替验收。`查看状态.cmd`也可查看各授权群的当前模式。
